# RAG Chat App

A per-conversation RAG (Retrieval-Augmented Generation) chat application. A user starts a conversation, uploads one or more files (PDF or plain text), and can then ask questions about those files — answers are generated by an LLM, grounded only in the content of the uploaded documents for that specific conversation.

Built as a learning project to get hands-on with RAG mechanics, Elasticsearch, and applying Redis for caching and session state — while producing something CV-worthy.

## Tech Stack

**Backend**
- **NestJS 11** — API framework
- **TypeScript**
- **Elasticsearch 9.3.3** — vector storage and kNN (k-nearest-neighbor) search for retrieval
- **Redis 7** — embedding cache, answer cache, and conversation/session state (all with TTL-based expiry)
- **Google Gemini API** (`@google/genai`) — `gemini-embedding-001` for embeddings, `gemini-3-flash-preview` for answer generation
- **unpdf** — PDF text extraction
- **Swagger** (`@nestjs/swagger`) — interactive API docs at `/api`

**Frontend**
- **Angular 20** (zoneless, standalone components, SCSS)

**Infrastructure**
- **Docker Compose** — runs Elasticsearch and Redis locally (backend/frontend run natively via `npm run dev`, not containerized, for simpler local hot-reload)

## Architecture / Workflow

**Uploading a file:**
1. File is uploaded to a specific conversation (`POST /conversations/:id/files`).
2. Text is extracted (`ExtractionService` — handles both plain text and PDF via `unpdf`).
3. Text is split into chunks (`ChunkingService` — paragraph-aware, with a sliding-window fallback for any single paragraph longer than the chunk size).
4. Each chunk is embedded into a vector via Gemini (`EmbeddingService`), with exact-match Redis caching so identical text is never re-embedded.
5. Chunks (text + vector + metadata) are indexed into Elasticsearch, tagged with the conversation ID and a generated file ID.

**Asking a question:**
1. The question is checked against an answer cache in Redis (exact-match, 1-hour TTL) — a repeat question skips retrieval and generation entirely.
2. On a cache miss: the question is embedded (same Gemini embedding model, but with `RETRIEVAL_QUERY` task type instead of `RETRIEVAL_DOCUMENT`, since Gemini's embeddings are asymmetric between the two).
3. Elasticsearch performs a kNN search, scoped to that conversation's chunks only.
4. The top-K retrieved chunks, plus the last few messages of conversation history (from Redis), are assembled into a prompt.
5. Gemini generates an answer, instructed to say "I don't know" rather than guess if the excerpts don't cover the question.
6. Both the question and answer are stored in the conversation's message history (Redis), and the answer is cached.

**Why Elasticsearch vs Redis, split this way:** Elasticsearch holds chunk content — the searchable, vector-indexed data retrieval actually queries. Redis holds short-lived, session-scoped data: the embedding cache (permanent, since a given text's embedding never changes) and conversation state — messages and metadata — which auto-expires (24h TTL) after inactivity.

## Data storage summary

| What | Where | Expiry |
|---|---|---|
| Chunk text + embeddings | Elasticsearch (`chunks` index) | None (persists until explicitly removed) |
| Embedding cache | Redis (`embed:{hash}`) | None (text → embedding is stable) |
| Conversation metadata | Redis (`conv:{id}:meta`) | 24h from last activity |
| Message history | Redis (`conv:{id}:messages`) | 24h from last activity |
| Answer cache | Redis (`answer:{convId}:{hash}`) | 1h |

## Setup

**Prerequisites:** Node 22+, Docker, a Gemini API key ([aistudio.google.com/apikey](https://aistudio.google.com/apikey)).

1. Clone the repo, install root dependencies:
```bash
   npm install
```
2. Install backend and frontend dependencies:
```bash
   npm install --prefix backend
   npm install --prefix frontend
```
3. Copy `backend/.env.example` to `backend/.env` (if present) or create `backend/.env`:

4. Start Elasticsearch and Redis:
```bash
   npm run infra:up
```
5. Start backend and frontend together:
```bash
   npm run dev
```
6. Backend API docs (Swagger): `http://localhost:3000/api`

## API Overview

| Endpoint | Purpose |
|---|---|
| `POST /conversations` | Start a new conversation |
| `POST /conversations/:id/files` | Upload one or more files (PDF/text) to a conversation |
| `POST /conversations/:id/search` | (Test/debug) Raw retrieval — returns top-K chunks for a query |
| `POST /conversations/:id/messages/ask` | Ask a question, get an AI-generated answer (full RAG flow) |
| `GET /conversations/:id/messages` | Get conversation message history |

Full interactive documentation is available via Swagger at `/api` once the backend is running.
